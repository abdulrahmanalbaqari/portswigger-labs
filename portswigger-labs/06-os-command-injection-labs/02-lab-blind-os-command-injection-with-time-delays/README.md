# Lab : Blind OS command injection with time delays

https://portswigger.net/web-security/os-command-injection/lab-blind-time-delays

- الفكره من الLab  ان الserver مبيبعتش  response  مش بيظهر تب احنا عاوزين نشوف هل هو فيه الثغره ولا لا هنجرب الكوده وهنلاقي delay 10 sec

```bash
1. ||ping+-c+10+127.0.0.1||
```

### الفكرة

في اللاب ده، التطبيق فيه ثغرة command injection زي اللي فات، بس المرة دي الـ output بتاع الأمر **مش بيظهر ليك في الرد** (ده اللي بيخليها "Blind"). يعني تقدر تحقن أمر لكن مش هتشوف نتيجته على الشاشة أو في الـ response مباشرة.

عشان كده، الطريقة الوحيدة إنك تتأكد إن الحقن نجح هي إنك تخلي الأمر ياخد **وقت أطول في التنفيذ** بشكل ملحوظ — يعني تستخدم أمر زي `sleep` أو `ping` وتراقب الفرق في زمن استجابة السيرفر.

### سيناريو اللاب

- بيكون فيه فورم "Submit feedback" في الموقع، وفيه حقل زي الـ email.
- في الباك اند، التطبيق بيبعت الفيدباك ده لسكريبت بيتنفذ على السيرفر (زي `feedback.pl`) وبيمرر قيمة الـ email من غير تعقيم.

### خطوات الحل

1. افتح الموقع وروح لصفحة "Submit feedback" واملى الفورم وابعته مرة عادي، عشان تشوف شكل الـ request.
2. افتح Burp Suite، فعّل Intercept، وابعت الفورم تاني عشان تمسك الـ request.
3. ابعت الـ request للـ Repeater.
4. في حقل الـ email (أو أي حقل بيتبعت للباك اند)، حط حقن زي:

```
||ping -c 10 127.0.0.1||
```

أو لو التطبيق شغال على Windows:

```
||ping -n 10 127.0.0.1||
```

1. ابعت الـ request وراقب الوقت اللي السيرفر ياخده عشان يرد.
    - `ping -c 10` معناها هيبعت 10 حزم، وده هياخد حوالي 10 ثواني تقريبًا.
    - لو الـ response اتأخر بشكل واضح (زي 10 ثواني بدل أجزاء من الثانية)، ده معناه إن الأمر اتنفذ فعلاً على السيرفر.
2. اللاب بيعتبر "محلول" تلقائيًا لما يكتشف إن فيه تأخير واضح في الاستجابة نتيجة الحقن ده.

#### ملاحظة عن الـ payload:

استخدام `||` قبل وبعد الأمر بيضمن إنه يتنفذ حتى لو الأمر الأصلي فشل، وده بيخلي الحقن أكتر موثوقية. ممكن كمان تستخدم:

```
; ping -c 10 127.0.0.1 ;
```

أو

```
& ping -c 10 127.0.0.1 &
```

### الاستفادة منه

1. **فهم Blind Vulnerabilities بشكل عام**: مش كل الثغرات بتديك رد مباشر، وده بيعلمك تفكر بطريقة غير مباشرة (out-of-band thinking) للتأكد من وجود الثغرة.
2. **تقنية Time-Based Detection**: دي تقنية أساسية بتتكرر في أنواع تانية من الثغرات زي:
    - Blind SQL Injection (زي `SLEEP()` في MySQL)
    - Blind XXE
    - SSRF
