# What is Server Side Template Injection (SSTI)

# Server-Side Template Injection (SSTI) - شرح مبسط

## هي إيه بالظبط؟

الثغرة دي بتحصل لما الـ server يستخدم "template engine" (زي Twig, Jinja2, Freemarker, ERB...) عشان يولّد صفحات HTML، وبدل ما الـ input بتاع اليوزر يتبعت كـ **"data"** عادية، بيتحط جوه الـ **template نفسه** كـ نص/كود.

النتيجة: المهاجم يقدر يكتب syntax خاص بالـ template engine، والسيرفر يفّسره وينفذه فعليًا — ده ممكن يوصل لـ **Remote Code Execution (RCE)** كامل على السيرفر.

## الفرق بين الاستخدام الآمن والخطير

**آمن (data):**

```php
$twig->render("Dear {first_name},", array("first_name" => $user.first_name));
```

هنا اسم اليوزر بيتبعت كـ variable، مش بيتلحّم مع الـ template.

**خطير (concatenation):**

```php
$twig->render("Dear " . $_GET['name']);
```

هنا الـ input بتاع اليوزر بقى **جزء من الـ template نفسه**. لو المهاجم كتب:

```
?name={{7*7}}
```

والسيرفر رجّعله `Dear 49` بدل ما ياخد النص زي ما هو، ده معناه إن فيه SSTI.

## إزاي تكتشفها (Detection)

فيه سياقين مختلفين:

### 1. Plaintext context

هنا انت بتحقن جوه نص عادي بيتعرض للمستخدم. بتختبر بمعادلة رياضية:

```
?username=${7*7}
```

لو النتيجة طلعت `49`، يبقى فيه evaluation بتحصل على السيرفر → مؤشر قوي على SSTI (مش مجرد XSS).

### 2. Code context

هنا الـ input بيتحط جوه **تعبير برمجي** جاهز، زي:

```
?greeting=data.username
```

طريقة الكشف:

- أول حاجة تتأكد إنها مش XSS عادية بحقن `<tag>`.
- بعدين تحاول "تكسر" الـ statement:

```
?greeting=data.username}}<tag>
```

لو الـ HTML اتنفذ بعد الـ `}}`، يبقى فعلاً قدرت تخرج من الـ expression وده دليل على SSTI.

**نصيحة عملية للـ fuzzing الأولي:** حقن مجموعة رموز زي `${{<%[%'"}}%\` — لو طلع error، ده أول إشارة إن الـ syntax بيتفسّر.

## إزاي تحدد نوع الـ Template Engine (Identify)

- أسهل طريقة: تبعت syntax غلط (زي `<%=foobar%>`) والـ error message نفسها غالبًا بتفضحلك اسم المكتبة وأحيانًا الإصدار.
- لو مفيش error واضح، بتجرب payloads مختلفة وتلاحظ أنهي واحد اتفّسر صح (فيه decision tree بيستخدمها الباحثين لده).
- **مهم:** نفس الـ payload ممكن يشتغل في أكتر من engine بنتيجة مختلفة، مثلًا:

يعني متستعجلش تحكم من نتيجة واحدة بس.
    - `{{7*'7'}}` في **Twig** → `49`
    - `{{7*'7'}}` في **Jinja2** → `7777777`

## الاستغلال (Exploit)

بعد ما تتأكد من الـ engine، بتدور على payloads خاصة بيه توصلك لـ:

- قراءة ملفات حساسة على السيرفر
- تنفيذ أوامر (RCE)
- السيطرة الكاملة على السيرفر واستخدامه كنقطة انطلاق لهجمات تانية على الشبكة الداخلية

## إزاي تحمي نفسك منها (Prevention)

1. **متسمحش لليوزر يعدّل أو يبعت templates خالص** لو ينفع.
2. لو لازم، استخدم **"logic-less" engine** زي Mustache — الفصل بين اللوجيك والعرض بيقلل المخاطر جدًا.
3. **Sandboxing**: شغّل الكود في بيئة معزولة (زي Docker container) وشيل أي functions خطيرة من متاح الاستخدام.
4. الأهم: **متعملش concatenate للـ input جوه الـ template string** — دايمًا ابعته كـ data زي المثال الأول.
