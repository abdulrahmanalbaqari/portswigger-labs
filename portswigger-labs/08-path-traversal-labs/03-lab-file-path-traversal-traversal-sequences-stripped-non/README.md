# Lab : File path traversal , traversal sequences stripped non-recursively

https://portswigger.net/web-security/file-path-traversal/lab-sequences-stripped-non-recursively

- الفكره من الLab ده  ان الموقع بتجاهل الsequence الخاص ب path traversal فا هنحاول ن bypass ليه فا ممكن نجرب ده

```bash
1. GET /image?filename=....//....//....//etc/passwd 
```

### الفكرة العامة

هنا السيرفر بيحاول يحمي نفسه بإنه يشيل `../` من الـ filename، لكن الفلترة دي بتتنفذ **مرة واحدة بس** (non-recursive) — يعني مش بتكرر العملية لحد ما تتأكد إن مفيش `../` باقية.

### المشكلة (الـ bypass)

لو بعتّ سلسلة زي:

```
....//
```

الفلتر بيدور جوه الـ string ويلاقي `../` في النص ده، ويشيلها **مرة واحدة فقط**. بعد ما يشيلها، الحروف اللي فضلت حوالين المكان اللي اتشالت منه بتتلحم مع بعض وتكوّن `../` تانية من جديد!

خلينا نبص عليها حرف حرف:

```
....//
```

لو افترضنا إن الفلتر بيدور على `../` بالظبط، هيلاقيها هنا:

```
..  .  .  /  /
```

الطريقة الشائعة إن الـ payload بيتكتب كده: `....//`  → لو شلت `../` من النص ده (اللي هو أربع نقط وسلاشين)، الأربع نقط دي فعليًا بتتكون من:

```
.. + ../
```

يعني الجزء الأول `..` + الجزء اللي هيتشال `../` → بعد الحذف يفضل `..`  و بعده `/` من الجزء الباقي، فتتكون `../` تاني كنتيجة نهائية.

**ببساطة الفكرة العملية:**

- بدل `../` اكتب `....//`
- كل ما السيرفر يشيل `../` مرة، الباقي بيبقى `../` من جديد
- كرر السلسلة دي بدل كل `../` في الـ payload الأصلي

### خطوات الحل عمليًا (Burp Suite)

1. اعترض الـ request بتاع صورة المنتج:

```
   GET /image?filename=product1.jpg
```

1. ابعته على Repeater.
2. غيّر الـ filename لتكون:

```
   filename=....//....//....//etc/passwd
```

(بدل كل `../` استخدمت `....//`)

4. ابعت الريكوست، ولو الفلترة non-recursive، السيرفر هيشيل الجزء `../` من كل `....//` ويتبقى `../` فعلية، فيتكون المسار النهائي:

```
   ../../../etc/passwd
```

وبالتالي يقرا `/etc/passwd` بنجاح.

### ليه ده بيحصل تقنيًا

الكود شبه:

python

```python
filename = filename.replace("../", "")   # مرة واحدة بس، مش loop
```

لو الـ input هو `....//`، فالعملية بتشتغل كده:

- الـ regex/replace بيدوّر ويلاقي `../` جوه `....//` (النقط التالتة والرابعة + أول سلاش)
- بيشيلها، فيتبقى `..` (النقطتين الأوليين) + `/` (السلاش التاني) = `../`

فالنتيجة النهائية بعد "الحماية" هي نفسها اللي كنت عايزها من الأول.

### الدرس المستفاد

- الفلترة لازم تتكرر (recursive) لحد ما محدش يقدر يلاقي أي traversal sequence تانية، أو الأفضل تستخدم **loop** بيشيل لحد ما الـ string يستقر (يعني تفضل تشيل لحد النتيجة متتغيرش).
- أي حل "sanitization" بيعتمد على `replace` أو `remove` مرة واحدة بيبقى دايمًا عرضة لل bypass بالطريقة دي.
- الحل الصح فعليًا مش الفلترة أصلاً، لكن التحقق من الـ **canonical path** بعد الـ resolve، والتأكد إنه بيبدأ بمسار الفولدر المسموح بيه.
