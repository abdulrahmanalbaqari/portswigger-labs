اللاب ده من فئة **Information Disclosure**، وتحديدًا **تسريب معلومات حساسة عن طريق تاريخ نظام التحكم في الإصدارات (Version Control History)**.

الفكرة الأساسية: الموقع بيستخدم **Git** لإدارة الكود، لكن فولدر **`.git/`** اتنشر بالغلط على السيرفر الحي (production) بدل ما يتشال قبل الرفع. فولدر `.git/` مش مجرد "الكود الحالي" — هو **أرشيف كامل لكل نسخة قديمة من الكود على مر الزمن**، بما فيه أي بيانات كانت موجودة قبل كده واتشالت لاحقًا. فلو أي حد وصل للفولدر ده، يقدر "يرجع بالزمن" ويشوف حاجات المفروض متبقتش ظاهرة أبدًا.

### الفايدة من اللاب (إيه اللي بنتعلمه)

1. **إزاي تكتشف إن `.git/` مكشوف** على أي موقع حقيقي.
2. **إزاي تحمّل مستودع Git بالكامل** من سيرفر بعيد من غير ما يكون عندك صلاحية وصول رسمية.
3. **إزاي تستخدم أوامر Git (`log`, `show`, `diff`)** عشان "تحفر" في تاريخ الكود وتلاقي بيانات حساسة اتشالت قبل كده.
4. الدرس الأمني الأهم: **أي سر (password, API key) ظهر مرة في تاريخ Git يُعتبر محروق للأبد**، حتى لو "اتشال" من آخر نسخة — لازم يتغيّر فعليًا مش بس يتشال من الكود.

### خطوات الحل بالتفصيل (شرح كل خطوة في الـ Solution الرسمي)

#### 1. تصفح `/.git` للتأكد إن البيانات مكشوفة

افتح اللاب وجرب:

```
https://YOUR-LAB-ID.web-security-academy.net/.git/
```

لو الفولدر ده متاح (بيديك رد بدل 404)، يبقى تأكدنا إن الثغرة موجودة، والخطوة الجاية هي استغلالها.

#### 2. حمّل الفولدر بالكامل

على أنظمة Linux، أسهل طريقة هي:

bash

```bash
wget -r https://YOUR-LAB-ID.web-security-academy.net/.git/
```

**الشرح**:

- `wget` أداة بتحمّل ملفات من الإنترنت.
- `r` معناها **recursive** — يعني حمّل الفولدر ده وكل الملفات والفولدرات الفرعية جواه بالكامل (زي `objects/`, `refs/`, `HEAD`, `config`، إلخ)، مش بس ملف واحد.

**ملحوظة**: إحنا في الشرح العملي استخدمنا أداة بديلة اسمها **`git-dumper`**، وهي أذكى شوية من `wget` العادي لأنها بتحاول "تخمّن" وتنزّل ملفات جوه `.git/` حتى لو مش ظاهرة في أي directory listing، وبتعيد بناء المستودع تلقائيًا. الطريقتين بيوصلوا لنفس النتيجة.

**ملحوظة لمستخدمي Windows**: الأمر `wget -r` من أدوات Unix، فمحتاجين بيئة تحاكي Linux زي **Cygwin**، أو استخدام أداة بديلة زي `git-dumper` (بايثون) اللي بتشتغل على أي نظام تشغيل.

#### 3. استكشف الفولدر اللي اتنزّل باستخدام Git المحلي بتاعك

بعد التنزيل، عندك دلوقتي نسخة كاملة من المستودع على جهازك. روح للفولدر وشغّل:

bash

```bash
git log --all
```

هتلاقي كوميت برسالة:

```
"Remove admin password from config"
```

الرسالة دي نفسها **مؤشر قوي جدًا** (information disclosure في حد ذاتها) — بتقولك بالظبط "دوّر هنا، كان فيه سر موجود قبل كده".

#### 4. افحص الـ Diff الخاص بالكوميت ده

bash

```bash
git show <commit-hash>
```

هتلاقي إن الكوميت ده **استبدل الباسورد المكتوب صراحة (hardcoded)** بملف `admin.conf` بمتغير بيئة (environment variable) اسمه `ADMIN_PASSWORD`:

diff

```diff
-ADMIN_PASSWORD=nook4hnth4k1t5txsny4+ADMIN_PASSWORD=env('ADMIN_PASSWORD')
```

لكن المفارقة: **الباسورد القديم لسه ظاهر بوضوح تام في الـ diff نفسه** (السطر اللي بيبدأ بـ `-`)! المطور "شال" الباسورد من آخر نسخة، لكن **نسي إن Git بيحتفظ بكل التاريخ**، فالباسورد القديم فضل محفوظ للأبد في الكوميت السابق.

#### 5. سجل دخول بالباسورد المسروق

ارجع للاب في المتصفح، وسجل دخول بـ:

```
username: administrator
password: <الباسورد اللي طلع في الـ diff>
```

#### 6. احذف carlos

بعد تسجيل الدخول، افتح **admin interface**، ودوس على زرار حذف بجانب `carlos`.

بمجرد ما تنفذ العملية دي، اللاب هيتحل تلقائيًا ✅.

### ليه ده بيحصل تقنيًا (السبب الجذري)

```
[سيرفر الإنتاج] ← اترفع عليه فولدر .git/ بالغلط ← أي حد يقدر يوصله عن طريق URL مباشر
```

المشكلة الجوهرية مركّبة من نقطتين:

1. **خطأ في عملية الـ deployment**: المفروض إن أي عملية نشر (deployment) للكود **تستثني فولدر `.git/`** تمامًا من النسخة اللي بتترفع على السيرفر الحي، لكن ده اتنسي أو اتعمل غلط.
2. **الاعتماد على "الحذف من آخر نسخة" كحل أمني كافي**: المطور افتكر إن مجرد شيل الباسورد من `admin.conf` كفاية، من غير ما يدرك إن Git **بيحتفظ بكل نسخة قديمة إلى الأبد** في تاريخه (إلا لو حد يعمل عملية متقدمة جدًا اسمها history rewriting، وهي نادرة وخطيرة على أي مشروع فريق).

### الدرس المستفاد

- **فولدر `.git/` (وكذلك `.svn/`, `.hg/` لأنظمة تانية) لازم يتمنع الوصول له تمامًا في بيئة الإنتاج** — إما بعدم رفعه من الأساس، أو بمنع الوصول ليه عن طريق إعدادات السيرفر (`location ~ /\.git { deny all; }` في Nginx مثلاً).
- **أي سر (secret) ظهر مرة واحدة في أي كوميت، حتى لو "اتشال" بعدين، يُعتبر مكشوف بالكامل وغير آمن للأبد** — الحل الوحيد الصحيح هو **تغيير السر فعليًا (rotate)**، مش بس حذفه من الكود.
- **رسائل الكوميتات نفسها (commit messages)** ممكن تكون مصدر تسريب معلومات — رسالة زي "Remove admin password" بتوجه أي مهاجم مباشرة للمكان اللي يدوّر فيه.
- أدوات زي **`wget -r`** أو **`git-dumper`** أساسية جدًا لأي محترف اختبار اختراق، لأنها بتحوّل ملفات بيانات "خام" (raw) من `.git/` المكشوف لمستودع Git شغال بالكامل تقدر تتصفح تاريخه بحرية.

**الفكرة**: مواقع كتير بتستخدم Git لإدارة الكود، وأحيانًا بالغلط بيرفعوا فولدر `.git/` **على السيرفر الحي (production)** بدل ما يفضل بس في بيئة التطوير. المشكلة إن فولدر `.git/` مش مجرد "كود حالي" — هو **أرشيف كامل لكل نسخة قديمة من الكود على مر الزمن**، بما فيه حاجات اتشالت أو اتعدلت بعدين. فلو حد وصل للفولدر ده، يقدر "يرجع بالزمن" ويشوف حاجات المفروض متبقتش ظاهرة.

### الخطوة 1: التأكد إن `.git/` متاح على السيرفر

#### عملنا إيه؟

bash

```bash
curl -v --http1.1 https://<lab-url>/.git/HEAD
```

#### ليه عملنا كده؟

عشان نتأكد **قبل ما نضيع وقت** في تنزيل أي حاجة، إن الثغرة أصلاً موجودة. لو الرابط ده رجع `200 OK` بمحتوى `ref: refs/heads/master`، ده دليل قاطع إن فولدر `.git` **متاح للعامة** ومحدش قفله. لو كان رجع `404`، كنا هنعرف إن الثغرة مش موجودة من الأساس ومكناش نكمل في الاتجاه ده.

**`.git/HEAD`** بالذات اخترناها لأنها أول ملف بيتقرا في أي عملية Git، وبتقولنا "إيه الـ branch الحالي" — يعني وجودها ورده صح دليل قوي إن الفولدر كامل موجود ومش بس ملف واحد اتسرب بالغلط.

### المشاكل اللي واجهتنا في الطريق (وليه حلينها بالطريقة دي)

#### مشكلة الـ 504 Gateway Timeout

**ليه حصلت؟** لابات PortSwigger بتقفل نفسها تلقائيًا بعد فترة من عدم الاستخدام، أو بعد وقت محدد من فتحها. الـ instance بتاعتنا كانت "ماتت" أو لسه بتتحمّل.

**ليه الحل كان "افتح اللاب من جديد"؟** لأن مفيش طريقة تانية "توقظ" الـ instance غير إنك تطلب instance جديد من الأساس (زرار Access the lab بيعمل provision لسيرفر جديد بالكامل).

#### مشكلة HTTP/2

**ليه حصلت؟** الـ curl بيحاول يستخدم أحدث بروتوكول متاح (HTTP/2) تلقائيًا، لكن سيرفر PortSwigger في اللحظة دي ماكانش بيرد عليه صح بالبروتوكول ده.

**ليه الحل كان `--http1.1`؟** عشان نجبر curl يرجع للبروتوكول الأقدم والأبسط (HTTP/1.1) اللي أغلب السيرفرات بتدعمه بشكل مضمون أكتر، وده استبعد احتمال إن المشكلة في التوافق بين curl والسيرفر.

#### مشكلة `.GIT` بدل `.git`

**ليه فرّقت؟** لأن مسارات الملفات في أنظمة Linux (اللي بيشتغل عليها أغلب web servers) **حساسة لحالة الأحرف (case-sensitive)**. يعني `.GIT` و`.git` اتنين مسارين مختلفين تمامًا بالنسبة للسيرفر، مش نفس الحاجة. الفولدر الفعلي اسمه `.git` بحروف صغيرة، فأي طلب بحروف كبيرة كان هيرجع 404 أو سلوك غريب.

### الخطوة 2: تنزيل الـ Git repository بالكامل

#### عملنا إيه؟

bash

```bash
python3 git_dumper.py https://<lab-url>/.git/ /home/kali/lab-repo
```

#### ليه عملنا كده؟

لأن السيرفر **مش بيدّيك واجهة تصفح لفولدر `.git`** (يعني مش زي directory listing عادي تقدر تشوفه في المتصفح)؛ فولدر `.git` عبارة عن **ملفات binary وbinary objects مضغوطة** بصيغة خاصة بـ Git، مفيش فايدة إنك تفتحها واحدة واحدة يدويًا.

أداة **`git-dumper`** بتعمل حاجتين:

1. بتحاول تخمّن وتنزّل **كل الملفات** المحتمل وجودها جوه `.git/` (زي `HEAD`, `config`, `objects/`, `refs/`, إلخ) عن طريق تجربتها واحدة واحدة كطلبات HTTP.
2. بعد ما تجمعهم، بتستخدم أوامر Git الداخلية عشان **تعيد بناء نسخة كاملة وشغالة من المستودع** على جهازك المحلي — وكأنك عامل `git clone` عادي للمستودع الأصلي، لكن من غير ما يكون عندك صلاحية وصول رسمية ليه.

بمجرد ما يكون عندك نسخة محلية شغالة، تقدر تستخدم **أي أمر Git عادي** (`git log`, `git show`, `git diff`) وكأنك واحد من فريق التطوير نفسه.

### الخطوة 3: فحص تاريخ الملف المستهدف

#### عملنا إيه؟

bash

```bash
cat admin.confgit log --all -- admin.conf
```

#### ليه عملنا كده؟

1. **`cat admin.conf`**: عشان نشوف **الحالة الحالية** بس للملف، ولقينا إنه بيقول:

```
   ADMIN_PASSWORD=env('ADMIN_PASSWORD')
```

يعني في النسخة الحالية، الباسورد **مش مكتوب صراحة** — بيتجاب من environment variable (وده تصرف صح أمنيًا لو اتعمل من الأول). فمفيش فايدة إننا نبص على الملف الحالي بس.

1. **`git log --all -- admin.conf`**: هنا استخدمنا خاصية مهمة جدًا في Git، وهي إنك تقدر **تفلتر الـ log على ملف معين بس** (بدل ما تشوف كل تاريخ المشروع كله اللي ممكن يكون فيه آلاف الكوميتات). ده وفّرلنا وقت كبير وخلانا نركز بس على **الكوميتات اللي أثرت على الملف ده تحديدًا**.

النتيجة كانت كوميتين، وكان أهمهم رسالة اسمها **"Remove admin password from config"** — والرسالة دي نفسها **كانت أول مؤشر قوي** إن فيه حاجة كانت موجودة قبل كده واتشالت. ده مثال حي على إزاي **رسائل الكوميتات نفسها ممكن تكون Information Disclosure** — لأنها بتقولك بالظبط "دورّ هنا، كان فيه سر هنا قبل كده".

### الخطوة 4: استخراج الباسورد القديم فعليًا

#### عملنا إيه؟

bash

```bash
git show 59d0a31a948a130003adba60affeddd556dad39e
```

#### ليه عملنا كده؟

`git show` على أي commit hash بتوريك **الفرق (diff) بالظبط** بين الكوميت ده والكوميت اللي قبله — يعني بالظبط **إيه اللي اتغيّر**. في حالتنا، الناتج كان:

diff

```diff
-ADMIN_PASSWORD=nook4hnth4k1t5txsny4+ADMIN_PASSWORD=env('ADMIN_PASSWORD')
```

السطر اللي بيبدأ بـ **`-`** معناه "السطر ده كان موجود واتشال" — وده **بالظبط** الباسورد القديم اللي كنا بندور عليه: `nook4hnth4k1t5txsny4`.

السطر اللي بيبدأ بـ **`+`** هو السطر الجديد اللي حل مكانه (النسخة الآمنة اللي بتستخدم environment variable).
