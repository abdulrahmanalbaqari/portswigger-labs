# What different between High level flow and Low level flow

**(المستوى العالي / الـ workflow بتاع الـ business process)**

- ده بيوصف الـ sequence الكامل اللي المفروض المستخدم يمشي فيه عشان يكمل عملية معينة، زي: تسجيل حساب → تفعيل الإيميل → إضافة منتج للسلة → تطبيق كوبون → الدفع → تأكيد الأوردر.
- الثغرات هنا بتظهر لما تقدر:
    - تتخطى خطوة (step skipping) — مثلاً تدخل على صفحة تأكيد الأوردر من غير ما تدفع.
    - تعمل الخطوات بترتيب غلط (out-of-order execution).
    - تكرر خطوة أكتر من المفروض (replay) زي استخدام نفس الكوبون أكتر من مرة.
    - تستغل الـ race condition بين خطوتين في الـ workflow.
- يعني التحليل بيكون على مستوى "العملية كلها" مش طلب واحد.

**Low-level flow (المستوى الأدنى / منطق كل خطوة/طلب لوحده)**

- ده بيركز على المنطق جوه خطوة واحدة أو request واحد بذاته، زي:
    - التحقق من قيمة parameter معينة (مثلاً quantity بتقبل رقم سالب فيقلل السعر).
    - منطق حساب السعر أو الخصم جوه نفس الـ endpoint.
    - state transition غلط جوه نفس الـ function (مثلاً تغيير status الأوردر مباشرة من غير المرور بالحالات المنطقية).
- هنا مش بتنظر للعملية ككل، بتنظر لصحة الـ logic جوه العملية الواحدة نفسها.

**خلاصة الفرق:**

|  | High-level flow | Low-level flow |
| --- | --- | --- |
| النطاق | العملية الكاملة (multi-step) | خطوة/طلب واحد |
| نوع الثغرة | تخطي/إعادة ترتيب/تكرار خطوات | خلل في validation أو حساب داخل نفس الخطوة |
| مثال | تخطي صفحة الدفع | تعديل السعر في request واحد |
